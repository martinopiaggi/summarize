# Errors and Troubleshooting

## Common Fixes

- **yt-dlp / platform errors:** ensure Cobalt is running (`docker compose` includes it) or set `COBALT_BASE_URL` in `.env` or `summarizer.yaml`
- **Missing API key:** add the provider key to `.env` (see `summarizer.example.yaml` for provider names)
- **No config file:** run `summarizer --init-config` or pass `--base-url` and `--model` with `--no-config`
- **Removed `audio-speed` key:** use `speed` in YAML, `--speed` on the CLI, or `speed` in API requests instead
- **ffmpeg not found:** install ffmpeg and ensure it is on your `PATH`

## Dependency and Install Issues

These problems come from the **Python environment**, not from summarizer logic. They are most common when many CLI tools share one `~/.local` site-packages directory and get upgraded at different times.

### pydantic / pydantic-core version mismatch

**Symptoms:** `summarizer serve` crashes at startup with an error about `pydantic-core` version mismatch, or a `SystemError` when importing pydantic. The CLI may work fine; the crash happens when uvicorn imports FastAPI → pydantic.

**Cause:** `pydantic` and `pydantic-core` must be installed as a matched pair. A partial upgrade — often triggered by installing or upgrading another tool that also depends on pydantic — leaves them out of sync.

**Fix (pick one):**

| Approach | Command |
|----------|---------|
| **Recommended — isolated reinstall** | `pipx install "martino-summarize[server]"` |
| **Dedicated venv** | `python3 -m venv ~/summarizer-venv && source ~/summarizer-venv/bin/activate && pip install "martino-summarize[server]"` |
| **Quick patch in current environment** | `pip install --upgrade pydantic pydantic-core` |
| **No local Python deps** | Use Docker (`docker compose up -d`) for the Streamlit GUI |

The quick patch fixes the immediate mismatch but does not prevent the next unrelated upgrade from breaking things again. Isolated installs are the durable fix.

### Server dependencies not installed

**Symptoms:** `Server dependencies not installed. Run: pip install 'summarizer[server]'`

**Fix:** Install the server extra in an isolated environment:

```bash
pipx install "martino-summarize[server]"
```

Or inside an activated venv: `pip install "martino-summarize[server]"`

### Import errors after upgrading other tools

**Symptoms:** Summarizer worked yesterday; today it fails with import or version errors after you upgraded groq, litellm, openai, or another Python CLI tool.

**Fix:** Reinstall summarizer in its own environment instead of debugging shared site-packages:

```bash
pipx reinstall martino-summarize
# or, for the API:
pipx install "martino-summarize[server]" --force
```

See [Installation](../getting-started/installation) for the full install method comparison.

## Error Types

| Exception | When It Happens |
|-----------|-----------------|
| `APIKeyError` | Missing or invalid API key |
| `APIError` | LLM request failed after retries |
| `ConfigurationError` | Invalid `summarizer.yaml` or missing required fields (including removed keys such as `audio-speed`) |
| `TranscriptError` | Could not extract or transcribe audio |
| `SourceNotFoundError` | Local file or URL is unreachable |
| `UnsupportedSourceError` | No downloader supports the URL |
| `VisualModeError` | Visual mode cannot be used for this source |
| `VideoValidationError` | Video exceeds provider duration/size/format limits |
| `AudioProcessingError` | ffmpeg or audio conversion failed |

## Transcript Sidecar Errors

With `sidecar-order: fallback`, the sidecar only runs after the local pipeline fails, so both reasons are reported together: `Local transcription: … | TranscriptFetch: …`. With `first`, a sidecar failure is shown only with `--verbose` (`[!] TranscriptFetch failed: …`) and the local pipeline takes over.

| Message | Fix |
|---------|-----|
| `TRANSCRIPTFETCH_API_KEY is not set in .env` | Add the key to the `.env` of the machine that runs the summarizer. For Raycast and the HTTP API, that is the server. |
| `Unknown sidecar '…'; use one of: none, transcriptfetch` | Fix `sidecar` in `summarizer.yaml`. The CLI and HTTP API reject invalid values before running. |
| `Unknown sidecar order '…'; use one of: fallback, first` | Fix `sidecar-order` in `summarizer.yaml` |
| `TranscriptFetch <code>: <message>` | The service refused the request, for example a private video or no credits left. The code and message come from TranscriptFetch. |
| `TranscriptFetch is still transcribing after 15 minutes` | Videos without captions are transcribed by a background job. Run the same source again later to collect the result. |
| `TranscriptFetch is unreachable: …` | Network or DNS problem between your machine and transcriptfetch.com |
| `TranscriptFetch returned HTTP …` or `returned no transcript segments` | Unexpected response from the service. Retry later. |

See [Transcript Sidecar](../integrations/transcript-sidecar) for setup.

## Configuration Errors

Requests that include the removed `audio_speed` field return HTTP `422` on the API. YAML configs with `audio-speed` or `audio_speed` raise a `ConfigurationError` at merge time. Use `speed` everywhere instead.

## Platform-Specific Issues

| Platform | Fix |
|----------|-----|
| Instagram / TikTok / Twitter | Set per-platform cookie files in `.env`, or run Cobalt as a fallback |
| YouTube (no captions) | Tool falls back to audio download + Whisper automatically |
| YouTube (blocks your server) | Use a [proxy](../integrations/proxy) or a [transcript sidecar](../integrations/transcript-sidecar) |
| Rate limits | Reduce `parallel-calls` in `summarizer.yaml` or retry later |

See [Cobalt](../integrations/cobalt) for downloader fallback setup and [Proxy](../integrations/proxy) for HTTP proxy configuration.
